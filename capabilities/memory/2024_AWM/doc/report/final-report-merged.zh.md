# 基于 Mind2Web 的智能体工作流记忆复现研究
 
**日期：** 2026 年 4 月

> 与英文版 `final-report-merged.md` 逐段对应；建议分屏或双栏对照阅读。

---

## 摘要

智能体工作流记忆（Agent Workflow Memory, AWM）是一种具有代表性的方法，用于让基于大语言模型的网页智能体从过往轨迹中获得可复用的程序性知识。原论文将 AWM 描述为广泛有效的记忆机制，报告了在 Mind2Web 与 WebArena 上的显著提升，并强调由语言模型诱导的抽象工作流的价值。本文对 AWM 开展一项**以 Mind2Web 为重点的复现研究**，并进行逐步与案例层面的分析。研究不止于聚合分数比较，而是评估论文关于 Mind2Web 的主要论断，随后通过逐步分解、475 步配对案例分析、C2 目标站结果追踪、工作流文本对比，以及经人工核验的提示级案例研究，追踪该方法的影响路径。

相较论文最宽泛的**性能**论断，最强支持出现在其**机制性**论断上。我们在文本层面确认：语言模型诱导的工作流始终比规则诱导的工作流更抽象；提示层面的代码与文本工作流表现相似；诱导得到的工作流库紧凑且重叠度低。相对地，在当前首轮证据中，离线 AWM 在七个站点上表现为混合而非普遍更优；在线 AWM 在更大的分布偏移下并不会变得更强；自然语言观测普遍优于 HTML 这一论断在三站评估中未获支持。

本报告的主要贡献在于解释 AWM **为何**在某些站点上帮助、在另一些站点上伤害。在正结果站点上，工作流产生的负面干预为零；在负结果站点上，负面干预在数量上显著超过正面干预。AWM 的实际影响窗口很窄，仅通过特定机制在 6–18% 的步骤上改变行为：在匹配站点上为策略重定向、取值格式纠正与过早终止预防；在不匹配站点上为领域误导、模板跳步与“工作流优先”行为。我们识别出原论文未讨论的八条边界条件，并总结出一个机制一致性解释框架，将工作流诱导质量、任务—工作流语义匹配与稀疏的逐步干预连接到聚合结果。

在 Mind2Web 上最可辩护的结论是：AWM 最好被理解为一种**条件有效的提示机制**，而非普遍可靠的记忆方法。其核心思想相较其最强的性能叙事，更能经受复现检验。

## 1. 引言

### 1.1 背景

大语言模型网页智能体常以无状态方式完成任务：每个回合被视为独立，智能体会丢弃刚刚发现的程序性模式。相比之下，人类网页用户会积累可复用的经验：搜索框通常在哪里、日期选择界面如何运作、何时浏览与何时搜索，以及如何识别重复的 UI 模式。

Wang 等人（2024）提出的智能体工作流记忆（AWM）旨在为网页智能体提供这类可复用的程序性引导。核心思想很简单：从成功轨迹中诱导工作流，将其存为可复用记忆，并在未来任务中重新注入提示。论文在两种模式下评估 AWM：

- **离线 AWM**：在测试前由带标注训练样本诱导工作流。
- **在线 AWM**：以流式方式，从智能体自身成功的测试时轨迹中逐步诱导工作流。

原论文报告在 Mind2Web 上步成功率相对提升 24.6%，在 WebArena 上任务成功率相对提升 51.1%，并在跨网站与跨领域泛化下进一步提升。

### 1.2 为何需要深度复现

对 AWM 而言，浅层复现并不足够。仅匹配少数聚合数字无法回答最重要的问题：

1. 该方法是否真的在任务、网站与领域之间普遍有效？
2. 若有效，究竟是何种逐步机制带来收益？
3. 若失效，它在何种边界条件下失效？

这些问题尤其重要，因为 AWM 同时提出多项雄心勃勃的论断：

- 工作流可以从经验中被抽象出来。
- 这些工作流可以在相关任务间迁移。
- 在线诱导在更大的分布偏移下会特别有用。
- 自然语言环境描述优于 HTML。
- 紧凑的工作流库仍可高度有用。

因此我们采用更深的复现策略：先核验主要论断，再解释机制，最后识别边界条件。

### 1.3 研究目标

我们的研究分三个阶段推进：

- **第一层：主要论断的复现。** 论文关于 Mind2Web 的主要论断在独立复现下是否成立？
- **第二层：机制解释。** AWM 通过哪些具体机制改善或损害逐步的智能体行为？
- **第三层：边界识别。** 原论文中哪些权衡、失效模式与条件性模式仍不清楚或未报告？

### 1.4 范围

本研究**仅限 Mind2Web**，且仅报告**首轮运行结果**。

- 主要证据基础**仅为 Mind2Web**。
- 所有正/负/混合判断均为**首轮判断**。
- 论文中的 `AWM_AS` 动作空间扩展实验**未覆盖**。
- 对齐率分析仅作为**探索性启发式**，而非强语义指标。

这些限制是有意的：它们减少过度断言，并使每条结论的地位明确。

### 1.5 主要贡献

相对典型复现报告，本研究贡献如下：

1. 对论文主要 Mind2Web 论断开展**站点层面的复现分析**。
2. **逐步分解** AWM 在动作类型与轨迹位置上的效应，揭示收益来自狭窄、依赖站点的干预，而非均匀分布的逐步帮助。
3. 一项 **475 步配对案例分析**，量化工作流在何时帮助、伤害、无效或多余，并表明 AWM 的实际影响窗口仅覆盖 6–18% 的步骤。
4. **六项经人工核验的提示级案例研究**，将正负面工作流机制追踪到具体的工作流—动作对应关系，并明确其因果边界。
5. **离线相对在线的权衡分析**，使原论文中的一条口头论断具体化。
6. **失效分类法与解释框架**，界定 AWM 在何处条件有效、在何处变得有害。

## 2. 相关工作

### 2.1 网页智能体基准

网页智能体评估已从 MiniWoB（Shi 等，2017）与 MiniWoB++（Liu 等，2018）等受限环境，演进到更贴近真实的基准。WebShop（Yao 等，2022）提供带众包指令的模拟电商站点。WebArena（Zhou 等，2024）整合五个网站，并以基于执行的功能正确性进行评估。Mind2Web（Deng 等，2023）强调跨任务、网站与领域的广泛覆盖，逐步评估指标包括元素准确率、动作 F1 与步成功率。我们的复现仅聚焦 Mind2Web，因为其明确的跨任务、跨网站与跨领域划分特别适合检验 AWM 的泛化论断。

### 2.2 大语言模型智能体中的记忆与经验复用

多种方法探索为 LLM 智能体配备超越当前回合的记忆。Synapse（Zheng 等，2024）检索相关训练样本作为轨迹级上下文。AutoGuide（Fu 等，2024）生成并选择状态感知指南。Voyager（Wang 等，2024a）在开放式具身环境中维护可执行技能库。AWM 在设计空间中占据独特位置：它学习**提示级工作流记忆**，而非检索完整轨迹或执行代码级技能。

这使 AWM 成为检验两个更广泛问题的有趣案例：

- 语言模型能否从轨迹数据中诱导可复用的程序性抽象？
- 这些抽象是否真能改善未来执行，而非仅作为描述性摘要？

### 2.3 工作流抽象与程序性复用

从经验中提取可复用程序的思想可追溯至程序综合与库学习（Ellis 等，2023；Grand 等，2023；Bowers 等，2023）。在智能体语境下，关键问题是：基于语言模型的诱导能否产生既足够抽象以跨任务泛化、又足够落地以改善逐步执行的工作流。AWM 通过比较基于语言的诱导（用占位符抽象掉样例特定取值）与基于规则的诱导（保留完整具体轨迹）来检验这一点。

### 2.4 作为机制性分析的复现

传统机器学习复现侧重匹配聚合指标。近期工作认识到需要超越分数表的更深复现实践：按子群分解结果、将收益追踪到具体模型行为，并识别边界条件（Dodge 等，2019；Bouthillier 等，2019）。本研究采用这一更强标准，将逐步分解、配对分析与提示级案例研究作为互补证据形式。

## 3. AWM 方法

### 3.1 问题设定

配备大语言模型骨干 *L* 与文本记忆 *M*（最初包含内置动作说明）的网页导航智能体，根据自然语言指令完成任务。在每一步，智能体观察当前页面状态并生成动作。AWM 通过从过往经验中诱导可复用工作流并将其注入 *M* 来增强这一循环。

### 3.2 工作流表示

每个工作流包含两部分：（1）概括工作流高层目标的自然语言描述；（2）一系列步骤模板，每步包含环境状态描述、推理轨迹与可执行动作。关键是，语言模型诱导的工作流用参数化占位符替换样例特定取值（例如用 `{search-term}` 代替 “dry cat food”），以增强跨任务可复用性。

### 3.3 离线诱导

当存在带标注训练样本时，AWM 以离线模式运行。给定网站的所有训练样本被拼接进单一提示，语言模型将常见子程序提取为工作流。这些工作流在测试前冻结，并统一注入所有测试样本的提示。此方法在此处的承诺是：从训练数据诱导的工作流应足够抽象，以迁移到同站上的未见任务。

### 3.4 在线诱导

若无训练样本，AWM 以在线模式运行。智能体顺序处理测试查询；每个任务结束后，基于语言模型的评估器判断成功与否。成功轨迹用于诱导新工作流，并在记忆中累积以供后续任务使用。这产生滚雪球效应：后续任务受益于更早成功所诱导的工作流。论文认为这在更大分布偏移下特别有用，因为工作流来自测试时而非训练时经验。

### 3.5 规则诱导基线

作为消融，论文提出基于规则的诱导：直接抽取每条唯一经验的动作序列而不做抽象。这产生完整具体轨迹的拷贝，而非参数化子程序，作为隔离语言模型抽象贡献的对照点。

### 3.6 Mind2Web 评估协议

在 Mind2Web 上，每个任务有固定步数。逐步评估衡量：

- **元素准确率** — 是否选中正确页面元素
- **动作 F1** — 该元素上的动作是否正确
- **步成功率（SR）** — 元素与动作是否均正确
- **任务成功率** — 任务中所有步骤是否均成功

基准提供三种评估划分：**跨任务**（同站、不同任务）、**跨网站**（同领域、不同网站）与**跨领域**（完全不同领域）。

## 4. 实验设置与分析方案

### 4.1 评估的论断

我们评估论文 Mind2Web 部分的五组论断：

| 设定 | 论文论断 | 本研究的评估 |
|--------|-------------|-------------------------|
| **离线跨任务记忆** | 离线 AWM 提升跨任务步 SR | 在 7 个网站上对比离线工作流与无工作流 |
| **在线跨站泛化** | 在线 AWM 在更大分布间隔下仍能泛化 | 在跨任务（kayak）、跨网站（tripadvisor）、跨领域（reddit）上使用在线工作流 |
| **语言模型 vs. 规则诱导** | 语言模型诱导优于规则诱导 | 在 3 个网站（newegg、united、kayak）上对比语言模型与规则工作流 |
| **表示消融** | 代码/文本差异小；自然语言观测优于 HTML | 在 kayak 上对比代码/文本；在 3 个网站上对比自然语言/HTML |
| **工作流质量** | 紧凑、高效用、低重叠的工作流库 | 在 3 个网站上进行工作流文本分析 |

### 4.2 模型与数据

实验在 Mind2Web 上使用 **GPT-4o** 与 **Qwen-3.5-397B-A17B**（全文简称 Qwen）。评估站点包括 kayak、newegg、united、budget、sixflags、yellowpages、kohls，以及用于在线泛化设定的跨站目标 Tripadvisor 与 Reddit。

### 4.3 分析方法

为超越聚合分数比较，我们使用四种互补分析工具。

#### 4.3.1 逐步分解

我们沿三个维度分解“工作流减基线”的差值：

- **按动作类型**（CLICK / TYPE / SELECT）：区分收益来自元素落地还是动作/取值引导。
- **按步骤位置**（前半/后半）：检验工作流是在任务启动时帮助还是贯穿轨迹。
- **按网站**：对比复现与未复现站点。

#### 4.3.2 配对案例分析

对每项任务的每一步，我们将基线—工作流配对分为四类：

| 类别 | 基线 | +工作流 | 解释 |
|----------|----------|-----------|---------------|
| **正面** | 0 | 1 | 工作流确实有帮助 |
| **负面** | 1 | 0 | 工作流造成伤害 |
| **无效** | 0 | 0 | 工作流无差别 |
| **冗余** | 1 | 1 | 工作流不必要 |

由此得到分布，揭示有多少步骤实际受工作流注入影响，以及净效应为正或负。

#### 4.3.3 提示级案例研究

选定的配对案例可追溯到原始 JSON 提示与动作输出。这允许在案例层面解释机制：输出变化是否可归因于某条具体工作流指令。

#### 4.3.4 辅助分析

我们还使用 C2 目标站结果追踪、工作流文本对比、探索性对齐启发式、直接的离线相对在线对比，以及前缀级在线学习曲线，以强化主要复现发现。

## 5. 复现结果

### 5.1 主要复现发现

**表 1. 主要复现发现汇总。**

| 论断 | 证据基础 | 主要发现 |
|-------|----------------|--------------|
| **离线跨任务记忆**：离线 AWM 提升跨任务步 SR | Mind2Web 首轮运行 | 混合；7 站中 2 站为正、2 站为负、3 站为混合 |
| **在线跨站泛化**：在线 AWM 在更大间隔下泛化 | Mind2Web 首轮运行 | 总体方向未获支持 |
| **语言模型 vs. 规则诱导**：语言模型诱导优于规则诱导 | Mind2Web 首轮运行 | 文本层面差异强支持；性能优势为混合 |
| **表示消融**：代码/文本相似；自然语言优于 HTML | Mind2Web 首轮运行 | kayak 上代码/文本获支持；三站评估后自然语言优于 HTML 未获支持 |
| **工作流质量**：紧凑、高效用、低重叠库 | Mind2Web 首轮运行 | 在提示级代理下获支持；效用代理仍较宽松 |

这已经揭示一种不对称：论文的**机制性与结构性**论断，比其最强的**性能与泛化**论断更站得住脚。

### 5.2 离线 AWM 与跨任务泛化

离线层面的故事是混合的，而非普遍为正。有些站点受益，有些退化，有些保持真正的混合。

#### 5.2.1 按动作类型的逐步分解

**表 2. 按动作类型的逐步差值（offline_wf − no_workflow，GPT-4o，跨任务）。**

| 网站 | 结果 | CLICK ΔElem | CLICK ΔSR | TYPE ΔActF1 | TYPE ΔSR |
|---------|---------|------:|------:|------:|------:|
| kayak | positive | +10.7% | +10.7% | +1.4% | +0.0% |
| newegg | positive | +9.1% | +6.1% | +50.0% | +33.3% |
| united | mixed | +0.0% | +0.0% | +19.5% | +28.6% |
| budget | negative | **−12.1%** | **−12.1%** | +8.4% | +9.1% |
| sixflags | negative | **−6.1%** | **−6.1%** | +0.0% | +0.0% |

**TYPE 侧的取值引导是最稳定的正向效应。** 即使在负结果站点上，TYPE 动作 F1 仍有提升（budget +8.4%）。工作流提供取值模板——城市名、搜索关键词、价格区间——帮助模型无论站点匹配质量如何都能选择正确输入。

**CLICK 侧的落地是跨站点分歧的主要来源。** 正结果站点的 CLICK 元素准确率提升约 +9–11%；负结果站点退化 −6% 至 −12%。工作流提供的元素描述在与目标 HTML 结构匹配时有帮助，不匹配时则主动误导。CLICK 表现是区分正负结果的首要因素。附录 A1 提供支撑这些动作类型论断的逐步汇总。

#### 5.2.2 按轨迹位置的逐步分解

**表 3. 按轨迹半段的步 SR 差值（offline_wf − no_workflow，GPT-4o，跨任务）。**

| 网站 | 结果 | 前半 ΔSR | 后半 ΔSR |
|---------|---------|------:|------:|
| kayak | positive | +0.0% | **+13.0%** |
| newegg | positive | +4.4% | +7.1% |
| budget | negative | −1.9% | **−10.9%** |
| sixflags | negative | −5.9% | −3.3% |

工作流效应沿轨迹累积。在 kayak 上，全部收益来自后半段（+13% 对 +0%）。在 budget 上，退化在后半段加剧（−10.9% 对 −1.9%）。AWM 不只是“第一步提示”——其影响随轨迹变长而放大，要么放大帮助，要么放大伤害。

#### 5.2.3 配对案例分布

**表 4. 配对案例分布（GPT-4o，跨任务，7 站共 475 对配对步）。**

| 网站 | 结果 | 正面 | 负面 | 无效 | 冗余 | 净 |
|---------|---------|------:|------:|------:|------:|------:|
| kayak | positive | 3 | **0** | 22 | 23 | +3 |
| newegg | positive | 5 | **0** | 56 | 26 | +5 |
| united | mixed | 3 | 2 | 35 | 23 | +1 |
| budget | negative | 6 | **12** | 53 | 28 | −6 |
| sixflags | negative | 3 | **6** | 23 | 32 | −3 |

出现三种模式：

1. **在正结果站点上，工作流从不伤害智能体**（负面 = 0）。AWM 要么帮助要么无作为，从不误导。这种“不造成伤害”的性质是 AWM 生效的关键前提。
2. **在负结果站点上，负面干预在数量上显著超过正面干预。** Budget 为 12 次负面对 6 次正面；sixflags 为 6 对 3。当工作流与目标站点不匹配时，它成为净伤害来源。
3. **AWM 的实际影响窗口很窄。** 无效步骤占全部步骤的 45–65%。工作流仅在 6–18% 的步骤上真正改变模型行为。聚合步 SR 的提升由少数决定性干预驱动，而非均匀的逐步引导。

附录 A2 记录本小节使用的、校正后的 475 步配对案例总计。

## 6. 机制性分析

### 6.1 收益来自何处

最稳定的收益通道是 **TYPE 侧取值引导**。工作流帮助模型提供正确类型的参数、取值格式或标签目标。即使在对 AWM 整体有害的站点上，该通道仍为正。

更脆弱的通道是 **CLICK 侧落地**。仅当工作流语言与站点操作结构匹配时该通道才有效；在匹配站点上有帮助，在不匹配站点上成为错误锚定来源。

### 6.2 稀疏干预而非均匀引导

配对分析表明，工作流并未施加连续控制。多数步骤为无效或冗余。AWM 不应被理解为“引导整条轨迹”，更好被理解为偶尔改变高杠杆决策的**稀疏干预机制**。

### 6.3 提示级正向机制

六项经人工核验的案例研究（三正三负）已追溯到原始 JSON 提示。六项均已在原始数据文件上确认。代表性正面案例见附录 B1 与 B2。

#### P-1：防止过早终止（kayak，任务 1，第 9 步）

**任务：** “Find the cheapest Hawaii package for two adults from June 18 to 21”

| | 基线 | 工作流 |
|---|---|---|
| step_success | 0 | **1** |
| 模型输出 | pred_act 为空；输出关于租车的自然语言摘要（幻觉） | `CLICK [57318]`（按最便宜排序） |
| 失效模式 | 模型幻觉任务完成，输出无依据文本 | — |

**机制：** 工作流 8（`View and Select Deals`）提示“在结果页 HOVER/CLICK 查看优惠”，防止过早终止。

#### P-2：策略重定向（newegg，任务 4，第 0 步）

**任务：** “Find a new drone priced between 25 to 50 dollar and ships from USA...”

| | 基线 | 工作流 |
|---|---|---|
| step_success | 0 | **1** |
| 模型输出 | `CLICK [10463]`（电子产品类目导航） | `TYPE [126] [drone]`（搜索框） |
| 失效模式 | 默认“浏览类目”策略 | — |

**机制：** `search_and_apply_filters` 工作流的第一步为 `[searchbox] Search Site → TYPE: {search-term}`，将策略从“先浏览”重定向为“先搜索”。

#### P-3：取值格式纠正（newegg，任务 5，第 3 步）

**任务：** “Find bluetooth vertical mouse with most reviews and add two to my shopping cart.”

| | 基线 | 工作流 |
|---|---|---|
| step_success | 0 | **1** |
| 模型输出 | `SELECT [112591] [5]`（数值下标） | `SELECT [112591] [Most Reviews]`（字符串标签） |
| 失效模式 | 元素正确、取值格式错误 | — |

**机制：** `search_and_sort_items` 工作流使用带人类可读标签的 `SELECT: {Sorting criterion}`，引导模型输出标签字符串而非数值下标。

### 6.4 提示级负向机制

代表性负面案例见附录 B4、B5、B6。

#### N-1：域外工作流误导（budget，任务 0，第 0 步）

**任务：** “View the Emergency Sickness Plan policy certificates for Connecticut.”

| | 基线 | 工作流 |
|---|---|---|
| step_success | **1** | 0 |
| 模型输出 | `CLICK [128]`（预订） | `TYPE [1326] [08817]`（地点搜索中的邮编） |

**机制：** `search_and_select_location` 工作流将智能体重定向到在搜索框输入地点，跳过正确导航路径。

#### N-2：全领域误导（sixflags，任务 2，第 0 步）

**任务：** “Show the balance sheet and cash flow statement for fiscal year 2021 of Six Flags.”

| | 基线 | 工作流 |
|---|---|---|
| step_success | **1** | 0 |
| 模型输出 | `CLICK [103]`（投资者链接） | `CLICK [1042]`（Browse the Parks Below） |

| | 基线 | 工作流 |
|---|---|---|
| step_success | **1** | 0 |
| 模型输出 | `CLICK [46822]`（选日期） | `CLICK [47084]`（Book Now 链接） |

### 6.5 机制综合

正向机制共享一种结构：工作流在关键决策点提供**正确的操作模式**（搜索而非浏览、标签而非下标、继续而非停止）。负向机制结构不同：工作流提供**不适用的操作模式**，模型在可独立推理时仍跟随工作流。

案例证据与“工作流优先”行为倾向一致——当两者皆可用时，模型似乎优先遵循工作流指令而非独立推理。这应被理解为提示性案例证据，而非已证成的普遍规律。

## 7. 离线相对在线的权衡

原论文口头将离线与在线诱导框定为权衡，但未将该区分操作化。**我们的结果使这一对比更尖锐。**

**表 11. kayak 上离线与在线机制对比。**

| 相对 no_workflow 的差值 | CLICK ΔSR | TYPE ΔActF1 | TYPE ΔSR |
|-----------------------|------:|------:|------:|
| offline_wf | +10.7% | +1.4% | +0.0% |
| online_wf | +7.1% | +19.2% | +16.7% |

- **离线工作流**像从训练数据诱导的宽泛操作库。在 kayak 上，它们在 CLICK 侧落地上更强。包含通用旅行搜索原语（`enter location`、`select travel dates`、`select hotel filters`）。
- **在线工作流**像从近期成功轨迹诱导的压缩例程。在 kayak 上，它们在 TYPE/取值引导上更强。包含更窄、轨迹形的例程（`search_for_cars_kayak`、`select_location_kayak`）。

因此离线与在线不应被理解为简单排序：

- 离线**更宽更稳**，但易受训练—测试分布不匹配影响。
- 在线**更贴近测试**，但在更大偏移下更脆弱，因为局部塑形的 routine 可能在错误语境中被复现。

这比简单说“更大间隔下在线帮助更多”精确得多。附录 A7 汇总支撑该权衡的证据。

### 9.3 工作假设：双条件成功

基于首轮四站证据，我们提出工作假设（非已验证规则）：

> AWM 有效性 ≈ f（工作流可复用性 × 基线改进余量）

两个条件似乎均必要：

1. **工作流可复用性**：短且参数化的子程序，可匹配多项测试任务。Kayak/NewEgg 满足（每工作流 2–3 步，完全参数化）；budget 不满足（每工作流 5.8 步，领域特定序列）。
2. **基线改进余量**：基线 CLICK 准确率处于中段、仍有元素落地改进空间的站点。SixFlags（基线 CLICK 73.5%）在无帮助下已表现良好。

这是来自四站的事后观察，非已验证阈值。

### 9.4 Mind2Web 上的组合性

论文强调工作流组合是关键能力，展示简单工作流如何在 WebArena 上组合成更复杂工作流。在 Mind2Web 上，我们对工作流文本的阅读呈现更扁平的画面：

- **显式层次组合**（一工作流调用另一工作流）：未在任何 Mind2Web 工作流文件中观察到。
- **扁平子流复用**（通过链接短可复用 routine 完成任务）：在 kayak 与 united 上明显存在，1–4 步参数化原语可灵活组合。
- **模板打包**（长且站点特定的序列，仅在弱意义上作为可复用单元）：在 budget 上可见。

在 Mind2Web 上，AWM 主要表现为可复用 routine 的扁平库式子流复用，而非显式层次工作流组合。这使论文的组合叙事部分可见，但比基于 WebArena 的叙事弱得多、平得多。Mind2Web 组合性附录提供该解读背后的基于来源的阅读。

## 10. 失效分类法

分析识别出比论文讨论的更丰富的失效分类法。

**表 15. 失效分类法。**

| 失效模式 | 描述 | 严重程度 | 出处 |
|-------------|-------------|----------|--------|
| **工作流不匹配** | 工作流模板不适用于当前步，将智能体带离正确动作 | 高 | 第 5.2、6.4 节 |
| **目标站首轮结果较差** | 当前目标站结果表现为错误的早期动作模式，且部分设定下伴随更弱的候选质量；这仍属于结果追踪而非独立机制证明 | 高 | 第 5.3 节 |
| **累积误导** | 工作流伤害在轨迹后半段放大 | 中 | 第 5.2.2 节 |
| **过度具体** | 规则工作流保留过多源站具体取值 | 中 | 第 5.4.2 节 |
| **表示噪声** | 混合 desc_html 表示增加提示长度并稀释注意力 | 中 | 第 5.5.2 节 |
| **工作流无效** | 工作流存在但不影响模型输出（45–65% 步骤） | 低 | 第 5.2.3 节 |
| **SKIP 步膨胀** | 真值元素不在候选中，膨胀所有条件的失败计数 | 结构性 | 第 5.2 节 |
| **覆盖有限** | 5–7 个抽象工作流无法覆盖全部测试步操作类型 | 结构性 | 第 5.6 节 |

这些失效并非同一类型。有的来自工作流不匹配，有的来自候选质量，有的来自稀疏覆盖，有的来自提示结构效应。论文未讨论其中任一项。

## 11. 总体评估

### 11.1 主要获支持发现

最强支持的结论为：

- 语言模型诱导的工作流比规则诱导的更抽象（4/4 文本指标，三站均成立）。
- 提示级代码与文本工作流表示在测试站点上表现相似。
- 工作流库紧凑且低重叠。
- 在匹配站点上，工作流以零负面干预真实改善局部逐步执行。

### 11.2 主要未获支持论断

当前 Mind2Web 证据不支持：

- 在线 AWM 在更大分布间隔下变得更强。
- 自然语言观测普遍优于 HTML。
- 对 AWM 作普遍站间稳健的解读。

### 11.3 何种表述变得更精确

复现后，论文最宽泛论断可更谨慎地改写：

- AWM 并非普遍有效，而是**条件有效**。
- 工作流有用性稀疏而非遍及全程，仅在 6–18% 步骤上改变行为。
- 在线记忆并非在偏移下普遍更优，而是**更贴近测试但更脆弱**。
- 抽象有帮助，但仅在正确的操作差异条件下。
- AWM 的收益来自具体机制（策略重定向、取值引导、终止预防），而非泛化的“高层操作引导”。

## 12. 对效度的威胁

本研究有四项主要局限。

1. **仅限 Mind2Web。** 论文还报告 WebArena 结果，不在本研究范围内。论文中部分更强叙事（尤其围绕工作流组合）主要依赖 WebArena 证据。

2. **首轮判断。** 当前正/负/混合判断有信息量，但并非带方差界的重复试验估计。“未获支持”应读作“在当前首轮设定下未获支持”，而非“明确为假”。

3. **未覆盖 AWM_AS。** 论文动作空间扩展分支（第 5 节，表 9）未覆盖。这是本研究范围限制，而非矛盾发现。

4. **探索性对齐率。** 对齐率度量基于关键词重叠，非语义匹配。适合产生假设，不适合因果论断。

这些局限应理解为报告纪律，而非隐藏但书。

---

## 13. 结论与未来工作

### 13.1 总结

这项深度复现支持对 AWM 比原论文更审慎的图景。

该方法有真实机制。可复用工作流能改善逐步决策，尤其通过 TYPE 侧取值引导与匹配的 CLICK 侧落地。语言模型诱导的工作流确实比规则诱导的更抽象，工作流库也确实紧凑。这些是论文叙事中实质性、可复现的方面。

同时，在当前首轮证据中，复现不支持论文性能叙事的最强版本。在所测 Mind2Web 设定下，在线 AWM 在更大分布偏移下并未变得更可靠。自然语言优于 HTML 的论断也未在三站评估中泛化。AWM 的收益稀疏、依赖站点，且高度依赖工作流—任务匹配。

因此最可辩护的最终判断是：

**AWM 是一种可信且可解释的提示机制，但不是普遍可靠的记忆方法。其核心思想相较其最强的普遍性论断，更能经受复现检验。**

这正是批判性复现应揭示的。

### 13.2 未来工作

1. **重复试验与方差估计。** 将首轮判断转化为有统计依据的结论，需要多随机种子与置信区间的多次运行。

2. **由失效驱动的工作流修订。** AWM 目前缺乏修订或撤回有害工作流的机制。检测有害模式并修改或移除问题工作流的写回循环，可应对该方法最严重的失效模式。

3. **语义工作流选择。** 当前方法统一注入全部工作流。基于任务—工作法语义相似度的检索机制可减少不匹配带来的伤害。

4. **WebArena 复现。** 将分析扩展到 WebArena 可检验此处边界条件是 Mind2Web 特有还是 AWM 的结构属性。

5. **跨模型稳健性。** 在更广骨干模型上测试有助于区分方法层面性质与模型特定行为。
